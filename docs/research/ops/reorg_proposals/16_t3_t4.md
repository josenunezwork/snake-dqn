# Reorg proposals 16: T3 / T4 research packages

Proposals only; nothing here has been executed. Catalog: [../../catalog/t3_t4_packages.md](../../catalog/t3_t4_packages.md).

1. **Promote the T3 rollout engine to a stable library (highest value).** `research/t3_rollout_labels_20261015/engine.py`
   and `bank_engine.py` are the simulation core for T34 shadow/pathb/exit_b8/round0d and T35, yet live in a dated
   study folder and are reached via private names (`engine._restore_grid_views`). Proposal: a new module (e.g.
   `src/simd_env/rollout/` or `research/lib/rollout/`) that re-exports these symbols as a public API, with the T3
   package left byte-identical (ratified hashes). New code imports the library path; old code keeps working. Needs an
   owner/Fable decision because it touches src/ and import paths used by hashed T34 receipts.
2. **Same treatment for shared audit helpers.** `t4e_return_20261016.seed_audit`, `t4f_return_20261016.seed_audit`,
   `t3_screen_20261015.banks` act as the de-facto fresh-world audit library for 8+ later campaigns. A thin
   `research/lib/seed_audit` facade would make that dependency visible.
3. **Do not delete any T3/T4 package.** Every "dead" package is either imported transitively by a reusable one
   (t4e.collection -> t4c -> t4a_posthoc) or hashed by receipts. Instead, add a one-line `STATUS` note per package
   in a future README pass (README.md exists only for t3_screen and t4a_screen/t4a_posthoc).
4. **Misplaced T4c code.** The T4c screen lives inside `research/t3_screen_20261015` (`*_t4c.py`, `T4C_README.md`,
   `t4c_results/`). Record this in the catalog (done) rather than moving it; moving would break hashes and test imports.
5. **Stale launch-input copies.** `t4c_20261016/launch_inputs_before_*.json` and `t4e/t4f launch_inputs_*` variants are
   historical receipts; keep, but list them in the catalog/INDEX as superseded inputs if a future docs pass touches them.
