# O1 A100 runtime-retention acceptance

**Prepared-only candidate. No native acceptance or operational adoption is claimed.**
The binding round-36 ruling funds one bounded independent acceptance series at
4.8 aggregate allocation-hours / 48 units, including all attempts and reserve.
The current qualified broker and mutable qualification registry remain active
until acceptance and independent review complete. This package never writes that
registry. The separate qualification record is
[A100_RETENTION_QUALIFICATION.md](A100_RETENTION_QUALIFICATION.md).

The frozen executor runs the existing `final-only` acceptance implementation and
its CPU/L4 observer gates first, on the final executable inventory. Only PASS
permits the native A100 stage. A cold native family canary then compiles the
fixed extension, executes real CUDA action selection, exports immutable proof,
and fully releases its assignment. Main packets bind that independent canary;
there is no retained-canary promotion.

The comparison is two separately allocated cold main packets versus the same
fixed two main packets on one retained A100. Inputs, empty first-attempt ledger,
source, toolchain and logical work are frozen. Only canary receipt and measured
runtime cache pins are mechanically bound afterward, in create-only admitted
manifests. Each link has a fresh root, output, generation and receipt. Setup
includes environment verification/copy/publication and extension compile/load.
The wall comparison uses the same allocation-request-start to independently
verified-release interval in both arms, including transfers and handoff.

Acceptance requires at least **50% second-job setup reduction** and **25% total
allocated-wall saving**. It also requires a MISS_COMPILED then a
HIT_VERIFIED_IMPORT for the same binary hash/module/key. A surviving assignment
or environment HIT alone cannot pass. The synthetic workload qualifies the
transport/cache mechanism; every research family keeps its own native canary,
scientific acceptance and original caps.

Source capture supports the existing outage-only sparse archive fallback. The
Mac binds the pinned commit, Git tree and raw tree SHA-256 into the generation
specification; the existing source installer verifies its selected inventory
before readiness. A Git checkout independently rechecks its full tree. A sparse
archive uses the broker-attested full-tree identity and records
`source_origin: mac_verified_sparse_inventory`; it never claims the archive
contains the full Git tree. Authentication/404 failures remain ineligible for
fallback. Required retention helpers must be present in custom sparse source
inventories before allocation.

Native faults cover stopped Mac lease renewal, stale generation, intentional
child exit 23, rate-accounting refusal and corrupt export rejection. They must
produce the expected failure receipt, truthful stop evidence, and independent
backend disappearance. Lease faults must disappear within 300 seconds of
expiry, before broker fallback cleanup. Current-source independent offline
fault tests additionally exercise handoff cap, interrupted second launch and
durable recovery. Scientific failure is never treated as a mechanical retry.

The source-bound Codex-V fault review binds each of all eight named faults to a
specific passing JUnit test and its committed test-source SHA, the immutable
JUnit XML, full test log and report. The Mac reducer derives every native gate
from manifests, canary evidence, hardware/boundary snapshots, exports, cache
records, release receipts and session evidence. Supplied PASS flags are refused.
Its evidence-only result still needs a **separate independent native review**:


`source_inventory` is the actual path-to-digest mapping, not the illustrative
placeholder above. Production admission rehashes and regenerates the result
before trusting that review. It also requires ordinary transport qualification.
Release and serving changes remain outside this scope.

## Prepare without dispatch

Use the clean published candidate checkout. `prepare` validates committed source
and creates a fresh package, final-only plan, native templates, fixed inputs,
empty ledger, admission template and `DISPATCH.txt` without invoking Colab:

```sh
cd /Users/josenunez/Projects/ml/snake-dqn-retain
/Users/josenunez/Projects/ml/snake-dqn/venv/bin/python \
  -m research.colab_cli.retention_acceptance prepare \
  --repo /Users/josenunez/Projects/ml/snake-dqn-retain \
  --output-root /absolute/fresh/o1-acceptance-package
```

When preserving other account assignments, add `--other-assignments` with the
reviewed endpoint-to-positive-rate JSON map. The map is frozen before data;
unknown or changed assignments refuse, rather than patching evidence in place.
Every native manifest is 20 minutes or less (fault packets: 8 minutes), below
the 60-minute acceptance exemption. The two-link chain is 40 minutes / 6.6667
units maximum at the conservative 10 units/hour ceiling. The frozen maximum
liability is 28.5 job units; the series reserves another 9.6 units inside 48,
and its conservative packet-time inventory is 214 minutes inside 288. These
are maxima, not predicted burn. The ruling's forecast remains 2 A100 hours.

Before operator dispatch, create `boundary-admission.json` separately from its
immutable template. It must bind the plan, original sealed admission and T0,
current unencumbered allowance/liabilities and reviewed account map; it must
record a safe sole-A100 boundary that displaces no I0/Q5 or other required work.
`t0_json_pointer` identifies the original T0 field inside that SHA-bound sealed
JSON admission (RFC 6901); it must contain a positive epoch or timezone-aware
ISO 8601 instant equal to `t0_epoch`. A new or future T0 is refused.
The full 288-minute effective envelope must fit before the original utility
deadline; each subsequent allocation reserves its maximum against that same
absolute deadline again.
No second sprint A100 is authorized. Missing admission or expired original
round-28 deadline refuses before allocation.

Run exactly the command in the package's `DISPATCH.txt` through
`tools/ops/dispatch.sh --retention-acceptance`. The wrapper applies the low
priority floor, AC/open-lid guards and caffeinate. An execution marker consumes
the attempt; interruption is never an automatic retry. The series checks
remaining wall/unit liability before each next allocation. A completion needs a
separately reviewed fresh remaining-envelope package, at most two outcome-blind
completion attempts after verified mechanical failure, stop and missing units.

After execution, `reduce --plan /absolute/acceptance-plan.json` is read-only and
returns nonzero until every gate passes. Keep all failures and receipts. A
valid timing failure parks retention while cold qualified dispatch remains
available. Bundle economy is a separate I0 gate (at least 20% fewer allocated
minutes per completed valid cell), charged to I0 rather than O1.
