**Recommendation:** permit one separately reviewed replacement only if the user explicitly changes the zero-recovery policy for this documented preflight-only failure. Keep the failed qualification window closed and its source commit `aa3d0dd0` immutable. Do not rerun its controller, amend its admission, extend its deadline, or portray the replacement as a continuation of a successful attempt.

The root reports that the controller stopped before creating a run root or launching a supervisor or child: its manually duplicated candidate digest was 63 characters, while the admitted digest was the correct 64 characters. No qualification, model evaluation, or gameplay stage ran. This note relies on that reported scope; it does not independently inspect execution evidence or authorize a retry.

A narrow exception is defensible because a failure before any scientific output provides no candidate outcome on which to select a more favorable attempt. It therefore need not weaken the scientific comparison. However, the prior static review missed an executable identity mismatch. That review failure must remain visible, and the zero-recovery boundary cannot be silently reinterpreted after the event. Audit integrity, restoration, or a repaired launcher would establish no candidate improvement or promotion result.

## Non-negotiable conditions for a replacement

- **Explicit authorization:** the user permits exactly one new admission for this identified preflight-only failure. The exception does not cover partial qualification, model queries, gameplay, numerical failures, or later failures. No automatic further replacement is authorized.
- **Close and preserve the failed attempt:** retain its original intent, source identity, controller failure evidence, and closeout explaining why no run root, supervisor, child, checkpoint access, or numerical stage occurred. If that preflight-only classification cannot be supported, this proposed exception does not apply. Do not reuse its output namespace or deadline.
- **Repair the failure mechanism:** derive the controller's candidate guard from the single canonical capture identity, validate it as exactly 64 lowercase hexadecimal characters, and compare it with the admitted identity. Remove the handwritten duplicate. The replacement review must trace this actual executable comparison, rather than merely compare descriptive manifests.
- **Bind a new immutable attempt:** use a new source commit, prospective plan, reviewed source closure, output root, admission identifier, and deadline. Record the failed attempt and this explicit exception in the replacement's provenance. A fresh admission cannot erase time or operations consumed by the failed controller.
- **Preserve the scientific target:** retain original frozen lineage 6102, the same checkpoint roles, source/physical caps, scientific settings, thresholds, and seed derivation rules. Do not switch to its continuation child or select new settings based on the failure. All numerical stages remain unexecuted until the replacement is admitted.
- **Keep existing safeguards:** retain serialization, resource and checkpoint-access guards, attempted-operation accounting, create-only artifacts, independent review, audit, and the handoff reserve. The proposed new wall-clock allowance must be explicit; no unbounded repair loop or informal preflight execution is included.
- **Fail closed again:** any failure of the replacement ends that attempt under its stated policy. Any further proposal requires another user decision; the exception is not a standing permission to retry until qualification passes.

The alternative is to retain zero recovery without exception and end this qualification proposal. That is internally consistent but forfeits this route because of a launch-guard implementation defect, without obtaining behavioral evidence. My preference is the single explicit replacement above: it preserves the evidence boundary while making the policy change visible and reviewable. Root owns the final approval question and any subsequent implementation or admission.
