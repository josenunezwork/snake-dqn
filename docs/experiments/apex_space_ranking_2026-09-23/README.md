# Apex space-ranking continuation: admission stopped

The proposed study asked whether one fixed auxiliary ranking loss on Apex's existing vector61 free-space features could improve H256 food-and-survival reliability across three paired seeds. It would have restored each 20,000-update source parent, trained one new `space_rank` candidate to 40,000 updates using the original TRAIN96 native collection schedule, and compared final policies with completed H256 controls on a separately qualified held bank. The coefficient and margin slope were fixed at 0.05 and 0.5; the existing TD target, PER priority rule, optimizer, and target schedule were to remain canonical. This protocol was frozen for a finite window, but **no candidate was admitted to training or evaluation**.

Held-bank qualification stopped during descriptor exclusion checks, before constructing a native game or querying a model. Six descriptor sources totaling 480 cases had completed in memory, with zero recorded root-ID and raw-initial-tuple overlap against the proposed held cases. The next source, `rejected_action_fork`, raised `KeyError: 'food'`: its initial descriptor has no initial food coordinate, and its `second_*` fields describe a later event rather than an alias for initial food. The source-only implementation review missed that schema difference. The descriptor cache was never persisted, so the exclusion boundary did not pass. Continuing would require repeating completed extraction; the staged amendment prohibits that recovery, resampling, or relabeling. The original deadline has expired and the scientific window is closed.
