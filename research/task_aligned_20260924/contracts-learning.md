# CZ reuse and new mixed-task collector contract

Implemented source is artifact-local in `adapter.py`. It does not modify the production trainer, execute historical study modules, change enemy-input weights, or claim that the new S6 lifecycle is already qualified. Importing it uses only the standard library. Runtime construction, checkpoint loading, gameplay, and optimization require the runner's new-stage admission.

## Fixed parents and preserved learner

The cohort is all three CZ `enemy_visible` mark-4608 endpoints, seeds 2026096101–6103. `parent_spec` reads only each exact named `report.json` in the sibling artifact directory. `load_parent` later authenticates its frozen report and checkpoint bytes, validates the 30-parameter model/Adam layout and step ages, and compares full tensor-state digests with completed CZ metadata. The report, checkpoint hash, and parent binding travel with the new endpoint. No source checkpoint was read during implementation.

The preserved wrapper is the one specified in `runs/solo-food-pqn-enemy-access-implementation/model.py`: raster31v3, tactical channels 0–5, zero strategic input, scalars 0, 1, 12, 13, 14, all other inputs zero, Q output multiplied by 0.1. Inputs are copied before restriction. External resolved six-action masks are unchanged. The architecture, weights, enemy channels, and Adam moments are loaded intact. The full learner clock and action-collapse evidence are retained. Environment state, action RNG, and SGD permutation RNG are fresh; this is not exact trajectory resumption.

The completed parent metadata fixes gamma 0.997, lambda 0.65, Adam learning rate 0.0005/epsilon 0.00015, gradient clipping 10, epsilon 0.1, one exact-coverage SGD epoch, B256, and half-MSE. Stock PQN uses Huber, so `_half_mse_sgd` clones the canonical `_sgd` function with a local functional proxy replacing only its single two-argument loss call by `0.5 * mse_loss(..., reduction="mean")`. It does not monkeypatch the production module. The canonical target recursion, optimizer, guards, clipping, and sampling are retained. Numeric recovery snapshots are refreshed **after** restoration so recovery cannot restore random initialization.

## New physical task, explicit kernel boundary

`build_trainer(parent, runtime_seed, device, rollouts, initialize_runtimes=True)` creates one learner and three persistent E16 runtimes with actual S1, S2, and S6 worlds. `initialize_runtimes=False` permits all-three restoration checks without constructing unused worlds. `initialize_runtimes()` then creates exactly 48 world roots once. `update()` selects the fixed `[solo, s2, s2, s6, s6]` cycle and returns per-profile collection/target-SGD timings and cumulative physical counters. All three runtimes share one model, Adam, and update clock.

The numerical kernel receives hero-only `(T=16,E=16,S=1)` tensors. This singleton is a tensor dimension, not the physical roster. Stock PQN S2 lifecycle enums are not forged or relabeled. New checkpoints separately record `parent_config`, `task_contract`, actual rosters, schedule, per-profile rows, and episode counters; they never export the kernel's singleton as the effective world.

World mechanics remain v2, 1450×830, 300 ambient food, source max-capacity 400, length normalization 150, and Watch pre-move action selection. Allocation-only `body_storage_capacity=2*horizon+400` is 2448 for training and 6400 for H3000 evaluation; it does not change source mechanics or length normalization. This bounds storage for at most two food-growth events per frame. The existing `_TerminalHeroBatchSim` supplies no hero respawn, ordinary opponent respawn, and `train_mode=False`. No population-floor dynamics are substituted. S2 uses greedy food; S6 uses three greedy food and two explicitly defined random-safe opponents. The new random-safe rule chooses among allowed normal actions by SHA256 of seed/world/frame/slot; it is not asserted to be the stock random-safe policy identity.

Only finished lanes reset, at their next selected runtime rollout boundary, using derived per-profile/per-lane/per-episode world and action seeds. Dead or capped lanes remain frozen during the remaining rollout. Hero death is terminal, and live H1024 caps truncate. `prepared_preview` clones the actual world and advances Watch preparation on the clone; **live capped lanes are included**. The live food, respawn, and RNG state are untouched. The first T−1 successors reuse the next collected Q under the same weights. Corrected raster31v3 resolved-mask target semantics apply; the legacy trapped bit is not used. New qualification must establish these S6, inactive-lane, death, cap, preview, and body-storage obligations.

Reward remains native reward plus `0.1 * ambient_food_ate` on valid transitions whose hero remains alive. Corpse and boost-trail pellets are not ambient events. No mass reward, shaping coefficient, target clipping, reward normalization, or enemy-weight reset is introduced.

## Dose, counting, and saved state

The maximum is 39,060 rollouts × 256 scheduled hero slots = **9,999,360** rows per lineage. Actual valid rows can be lower. A rollout contains 1–256 valid rows and receives one optimizer step; every valid row is sampled once. Smaller terminal batches therefore retain the inherited per-update mean weighting. The 20/40/40 mixture is a scheduled-rollout ratio, not an episode or valid-transition guarantee. The qualification owner freezes the same hardware-only complete-cycle dose for all three lineages before science.

`PhysicalCounters` counts actual active native world-frames, valid hero and opponent transitions, model forward invocations and rows (including padded/inactive rows actually computed), successful optimizer steps, sampled valid draws, completed rollouts, preview calls, constructed world roots, checkpoint hashes, and deserializations. Preview preparation is not a native movement frame. Optimizer post-hooks count a step even if a later tripwire rejects the rollout. A successful training rollout normally makes 16 collection forwards, one final-target forward, and one B256 SGD forward. With E16, that is 528 evaluated rows, not 256.

`save_checkpoint(path)` uses exclusive creation and saves full learner state plus the separate physical task contract. `used_world_seeds()` regenerates every actually constructed world seed, including unfinished episodes, for the held-world collision audit. Candidate loading authenticates bytes and validates the new schema, layout, task contract, and completed frozen dose. Partial endpoints are admitted only through the explicit qualification-only `allow_partial` flag. Serving may use model weights alone after these checks; training restoration includes Adam.

## Serving and prospective qualification

`evaluation_factory(spec, policy)` returns the evaluator's runtime with CPU float32 `run_batch(requests)` and an E1 `run_episode` facade over the same implementation. A scientific cell has 32 independent procedural worlds with one profile and H3000; each lane stops at first hero death. Opponents continue to respawn while its hero lives. Mass is post-move logical length, with death frames zero. Encounters use pre-action head-to-any-live-enemy-body L1 distance at most 16. Initial descriptors bind geometry, food, and RNG before controller decisions. Fixed opponent random seed 0 is shared across all roles. Batched forward calls are recorded once in shared counters, never fabricated once per world.

`qualification_evaluation_probe(source, spec, seed, out, heartbeat)` reconstructs pristine CPU parent weights from already-loaded tensors, after the disposable training probe, without another checkpoint deserialization. It bounds learned throughput to three E32/H128 cells, scripted throughput to six E32/H32 cells, and E32-versus-E1 parity to 128 total frames. Parity checks prepared Q within rtol 1e−5/atol 1e−6, exact masks/actions, descriptors, and frame facts. Three synthetic H3000 report files measure serialization. Doubled gameplay/serialization forecasts plus 60 seconds of fixed overhead must fit each 900-second evaluation job. Short probes do not guarantee long-body throughput; guarded stage caps remain authoritative.

Static compilation and formatting are the only implementation validation performed. The new source has not loaded a checkpoint, run gameplay, or performed a learner update during this work. Required behavioral and restoration qualification remains an admission gate, and this package is neither causal identification of prior failures nor promotion evidence. The older CZ relative-retention and unchanged-S2-dose failures remain closed.
