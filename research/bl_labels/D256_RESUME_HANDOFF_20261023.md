# Original D256 continuation

This is an operational continuation of the original D256 series, not a new
scientific attempt, look, label, or admission. The original admitted control,
namespace, allocation, state directory and 57,600-second series wall cap stay
unchanged. Existing evidence in `mac-pack-02` is read-only.

`RUN_D256_RESUME.sh` is a synchronous body for the pinned `dispatch.sh --mac`
route. It verifies every start/terminal/output receipt, including attempts with
zero exported lives, before publishing a portable, outcome-blind union ledger.
It refuses missing terminals, INVALID attempts, duplicate unit IDs, foreign
wrappers, orphan outputs and exhausted wall caps. The union accepts only sealed
immutable payload/SHA/completion triplets. It invokes no scientific aggregator.
The registered rolling-rate stop remains terminal; it cannot be relabelled as
an operational preemption through this continuation path.

The next union is `mac-pack-02/d256-resume-02/verified-ledger.json`, then `-03`,
and the next output is `d256-output-mac-02`, then `-03`. Every collection uses
`d256-state-mac-01`. A check/lease refusal can reuse the exact verified union;
a verified subsequent preemption advances both paths on the next invocation.
The script runs the driver's `--check` before executing its run synchronously.
Use a fresh **dispatcher name** for each dispatch; the script body stays the same.

The coordinator is the new operational code. Admission is rechecked in a separate
process at `61900af28932e47e22e332840fc4406559adb062`, and every spawned collector
loads that complete frozen scientific import closure through `frozen_factory`.
The reference worktree is created/reused at
`/Users/josenunez/Projects/ml/snake-dqn-d256-resume-science.noindex`, detached,
clean and pinned. It never reuses the old run's worktree. New start and terminal
receipts identify the operational commit separately from the science pin and
driver hash.

Worker choice uses `d256_w12.select_workers`, the exact owner file, calibration
host-sample and runner provenance, and checkpoint hashes. A sealed PASS permits
W12; a sealed measured FAIL selects W6. With no calibration evidence at all,
W6 remains authorized. Partial, malformed, HOLD or foreign existing evidence
refuses launch. Direct driver W12 continuations also enforce the complete owner
and calibration rule. Ordinary D256 invocations gain no width-change exception.

The original driver sampled elapsed, worker-seconds and cumulative wall fields
at separate instants. Compatibility allows at most one millisecond of clock
difference only for a W6 legacy start attesting the exact original driver hash.
No historical receipt is rewritten. New denominators use the round-27 canonical
sum of `workers * elapsed_seconds`; each new receipt also retains the summed
historical recorded denominator in `prior_recorded_worker_seconds_denominator`.
All new-format charges are exact. Same-width baselines carry forward; width
changes keep separate baselines under the existing round-27 coordinator.

Verification uses synthetic exports and an inline fake collector. It includes
the original frozen driver's actual ledger reader and the synchronous shell
entrypoint's ledger-only path on a temporary fixture. Actual-pack checks read
only operational receipt/admission metadata and sealed calibration provenance.
No factory, calibration, timing, strict gate or serving job was launched.
