## Implementation / execution steps

1. Implement a counterfactual probe harness using cloned complete simulator/RNG state and controlled full joint actions. Verify clone independence and equal-observation witnesses.
2. After its tests pass and the root grants an exclusive CPU slot, collect at most 250k transitions with seed/opponent episode splits; reserve untouched test worlds.
3. Compare current observations, oracle omitted counters, short 2/4/8-step histories and simple enemy-head tokens. Report action-order disagreement and finite-horizon regret alongside predictive errors; define horizon/opponent sampling and practical threshold before opening test data.
4. No GRU, attention, new channels, crop or gameplay changes here. If results justify a candidate, emit a separate bounded implementation proposal with exact fields/capacity and fresh training protocol.

## Acceptance evidence

- Alias existence, prevalence, action preference and return regret are separate outputs. Counterfactual horizon return is not mislabeled globally optimal Q.
- No row-level split leakage across an episode/world/opponent checkpoint. Thresholds and resource limits are frozen before test evaluation.
- Corpus/probes run serially relative to MPS training and full tests; stop on the declared resource/time cap and preserve partial-corpus status.
