## Review findings and fixes

1. Funding verifies both frozen fit controls against their sealed allocations,
   retaining the existing ordered list-of-life-ID `reserve_allocation_sha256`.
   The held-out structured digest is carried as `reserve_ancestry_sha256`.
   `job.py` is unchanged, including every I3 identity and admission check.
   The integration tests derive identities from synthetic package producers
   and feed canonical funding output into the real I3 staging consumer.
2. R-A uses packet schema v2 and one fixed claim directory:
   `/Users/josenunez/Projects/ml/snake-dqn-artifacts/big-lever/exp/f4/r-a-claims`.
   The claim filename hashes registration, frozen series, and control reserve
   identity; input relocation, different outputs, or a second prepared packet
   cannot create another claim for that series/reserve. Claim publication is
   atomic and create-only. A failed or partial claimed invocation stays spent.
   Funding verifies every parsed invocation argument, input file identity,
   executing published source pin and source bytes, preflight lock identities,
   and output path before either held-out callback. Historical locks also refuse.
3. The packet binds JUDGMENT_D4096_START §4, the full authoritative D4096 start
   metadata set, its earliest start, and the F2 result-ledger publication commit
   on `origin/main` with its committer epoch. F2 must precede both
   2026-10-25 18:00 PT and the R-A claim; equality is late. Funding revalidates
   timing immediately before claiming. A start at or before 06:00 PT selects
   the wait-until-published-or-18:00 branch. Late/INVALID/NOT_RUN F2 uses the
   strikes branch. F2 cannot replace or reopen a claimed R-A look.

The timing authority is the I1 admitted pack at
`bl-labels-f0-speed/d4096-old-equiv-02-pack-01/`: original
`d4096-control.json`, `d4096-admitted.json`, and only
`d4096-state-mac-01/attempt-*.start.json`. Starts bind the admitted control's
canonical hash, not the original HOLD control's hash. Namespace, allocation,
OLD source identities, admission relationship, and judgment must agree.
Omitting `--d4096-start-receipt` still discovers the authoritative earliest
start; supplying it asserts that exact earliest receipt. New starts/admission
metadata after preparation make the packet stale and require a fresh packet
before any claim. No runtime result, rate, label, or lease is read for timing.

Publication-time evidence is the committer timestamp of the verified result
ledger commit reachable on `origin/main`; file mtimes and self-reported receipt
timestamps are not used. Unrelated later main commits preserve that identity.
