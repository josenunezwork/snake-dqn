# T4 levers re-ranked at margin 0.063 (advice, 2026-10-16)

Advisory note from the cloud session, sixth request. Not gate evidence. The bank margin is
`margin.json` 0.0632 x scale 1.0 = 0.063 Q units, 7x below T1's median fatal-versus-survivor
gap of 0.45. Overshoot is ruled out; raising the margin to 1.0 is withdrawn.

## What a 0.063 margin tells us

The hinge moved Q(greedy) below the best survivor by a hair on 11k states and the student
complied (bank_agree 0.995). That hair still cost 70-100 mass because the late-game action
landscape is nearly flat: median gaps under half a Q unit, so a small non-specific shift flips
many argmaxes in look-alike states. The lever is therefore not the margin size but the loss
shape: it needs a term that holds the greedy move up where it is right, so the network has to
find a discriminating feature instead of a blanket shift. If no such feature exists in bv8,
a symmetric loss will fail to fit both sides, and that failure is the most useful result we
can buy this cheaply.

## (a) Symmetric bank loss first: yes, cheaply

**Make counter rows active.** Today a counter row only says "non-surviving actions stay below
the best survivor", which already holds, so it has no gradient and cannot resist caution. Route
counter rows through the existing single-action margin (`anchor_loss_margin`, as the v8 anchor
does) with B8's action as the label: Q(B8 action) >= max over other actions + m. Decisive rows
keep `surviving_margin`. That is a loss-routing change on existing data.

**Raise the margin to about 0.3** on both sides, near T1's median gap, so a flipped ranking
survives TD noise instead of being re-flipped every epoch. Not 1.0.

**Counter sampling.** Bring the ratio to 1:1 by upsampling the 5.4k counters, and keep them
from the same length, frame and -max Q range as decisive rows (the Q prefilter already does
most of this). Matched counters are what force discrimination.

**Keep the hinge, not cross-entropy.** A softmax target never saturates and keeps pushing
after the ranking is right; saturation is the property we want.

**Danger-weighting** (down-weight decisive rows with low -max Q) is a second knob, not the
first: it trades the hard cases for less caution. Try it only if the two-sided loss still
loses mass.

**Readout to pre-register:** bank_agree on each side at 8M. Both above 0.9 means the inputs
carry the distinction and labels can work; decisive agree stuck below 0.8 while counter agree
holds means the states are ambiguous at the input, and the campaign's next step is inputs
(narrowest gap to the outside, k-frame boost-escape feasibility), not more label machinery.
One arm, five seeds, 8M, about 3-4 Mac-hours.

## (b) Minimal correct return-regression target

For a branch from s0 taking a0 then B8 greedy, with transitions t = 0..T-1, gamma 0.998,
Phi(L) = L/10, Phi(dead) = 0, death value -3, mass term kappa (1 - gamma) Phi(L_t+1) on alive
steps: the PBRS part telescopes, so the realised truncated return is

```text
G = kappa (1 - gamma) S - Phi(L0) + gamma^T Phi(L_T) [survivors only] - 3 gamma^(T-1) [died]
S = sum_{t=0}^{T-1} gamma^t Phi(L_{t+1}) alive_{t+1}
```

Target: y = G for a dead branch; y = G + gamma^T V(s_T) for a survivor truncated at D = 300,
with V(s_T) = Q_target(s_T, argmax_a Q_online(s_T, a)) under the mask, the trainer's own
double-DQN bootstrap. gamma^300 is 0.55, so the bootstrap carries half a survivor's target and
s_T must be stored. Loss: Huber on Q(s0, a) - y_a over actions with `outcome_recorded`, same
weighting as the bank. The target is "a then B8", an expert-rollout target, and should be
disclosed as such.

Record per branch: T, died, S (raw, before kappa (1 - gamma)), L0, L_T, and the packed
terminal observation plus mask for survivors. Record S raw so the bank stays valid under
another kappa or gamma. Nothing else is needed; final length alone cannot reconstruct S.

## (c) Order

1. Two-sided margin at 0.3 with matched counters, bank v2, five seeds at 8M: hours, and it
   doubles as the discriminability probe.
2. Return regression next, only if step 1 shows the inputs can fit both sides. It uses the
   same inputs, so it cannot rescue an ambiguous state; it fixes magnitude, not perception.
3. Snapshot restarts after, not before: they need an actor reset path and world clones, and
   they share the input limit. Build them in parallel while step 1 trains, since the
   engineering is independent of its result.
