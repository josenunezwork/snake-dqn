Implementer: Codex. Read AGENTS.md, then `docs/research/advice/2026-10-15_open_ideas.md` (the cloud
advisor's ideas; this spec implements its 1a, 2a, 2b-data and 2c), the T3 bank doc

Build tools only. Do NOT launch training or long collections. Development tooling, not gate evidence.

## Guardrails
- Never touch tmux t3-lane0 / t3-lane1 / t3-probe / git-sync or processes you did not start. The Mac
  is busy: at most 2 worker processes for any measurement, single-threaded; MPS use only in short
  measurements (< 5 min) because training lanes use MPS.
- Do not change default behaviour of `train_m3c.py`, `learner_m3c.py`, `dev_probe.py`, or the T2/T3
  probe packages; add new options default-off or new modules. Do not modify the existing bank files.
- Git: branch `t4prep-20261015` in this worktree. Commit often; after each commit
  `git fetch origin && git merge origin/main` (resolve only your own files; otherwise stop and
  report), `git push origin HEAD:main`, `git push origin t4prep-20261015`.

## A. Batched screen probe path (advisor 1a)
A screen-only probe mode: each (checkpoint, mix) as one GridBatchSim over all its worlds with one
batched hero forward per step (MPS if available, else CPU), same worlds/seeds/opponents/masks as the
T2 probe path. Measure: wall time vs the rowwise path on 1 checkpoint x 32 scripted worlds, and
decision agreement (fraction of hero decisions identical over the episodes, per-world outcome
agreement, mass/survival differences). Expect rare float-tie divergence; report it. Never used for
strict gates; a screen must use one path for all arms. Tests + a doc section.

## B. Bank v2 labelling (advisor 2c + 2b data)
1. Check whether the existing bank / provenance already holds per-action rollout outcomes
   (death frame, survived, final length). If yes, write an offline relabeller that produces a
   derived bank (new directory, new manifest, hash-bound to the source) with the
   SMALLEST-SUFFICIENT label: surviving non-boost actions when any exist, else the surviving boost
   set; report how many rows change and the new boost share. If not, add the fields to the collector
   (default-off flag `--record-outcomes`) so the next collection stores them, and say so.
2. Add `--label-policy {surviving-set, prefer-nonboost}` to the collector (default surviving-set).
3. Return-regression data: for each rolled-out action store survived flag, death frame (or null),
   final length at horizon, so a later trainer arm can regress Q(s,a) toward the realised branch
   return. Do NOT implement the trainer arm; write a short design note of the target formula
   consistent with the trainer's reward (mass term + PBRS, gamma 0.998, death value -3).

## C. Expert-iteration driver (advisor 2a)
A script `research/t4_expert_iteration_20261015/collect_for_student.py` that runs the T3
death-window collector with a given student checkpoint as both the played policy and the rollout
continuation policy, on a fresh namespace / round (seed audit like T3), writing a new bank with
the v2 labelling options. Validate on 2 worlds only (do not collect a real bank). Document the
command for a 2-hour collection.

## Deliverables
Tests for A, B, C (fast); flake8 clean; `docs/research/t4_prep_tooling_2026-10-15.md` describing
each tool, measurements (A timing + agreement; B relabel stats), and exact commands. Final message:
A speed-up and agreement, B relabel stats (or what is missing), C validation, commit sha.
