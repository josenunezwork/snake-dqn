## Implementation / execution steps

1. Implement the interfaces and semantic decisions in README.md: observation descriptor, effective world, runtime/episode mode, action mask set, run provenance, canonical JSON digest, and stable named RNG streams. Extend the existing compatibility validator; do not introduce another competing checkpoint validator.
2. Define raster31v3 with the same shapes and scalar slots. Require its complete semantic descriptor and digest; accept missing metadata only through named vector61/raster31v2 legacy adapters. Keep default legacy inference dispatch unchanged until S1 wires v3 atomically.
3. Add only the configuration fields needed by later packages, including an optional run seed and explicit contract/profile selection. Resolve CLI > environment device override > YAML > automatic selection. New behavior is opt-in until G0 passes.
4. Seed Python, NumPy and Torch before construction; derive named streams without wall clock or Python hash(). Return/persist an entropy-generated effective seed when no seed was requested. Export RNG state helpers with device limitations explicit.
5. Publish a small API/descriptor fixture in the package handoff. Downstream packages may read but cannot edit these files without a new scheduled C0 handoff.
6. ActionMaskSet resolves independently per action row: intersection = legal & advisory; return intersection if that row has any true action, otherwise legal. Dead rows stay false; never use one batch-wide any().
7. Expose the already validated pqn block as AppConfig.pqn using a frozen PQNOverrides value. Preserve None for a value not supplied; do not fill it with a second CLI default. P1 must consume one initialize_config/load result without opening or reparsing YAML. Preserve existing config API consumers.
8. Define ModelHeadContract and a closed descriptor registry for Apex/PQN action-Q heads and the optional PPO categorical actor plus scalar critic head. Keep algorithm identity distinct from observation identity. Validate declared head shapes and reject unknown combinations; descriptor recognition alone does not enable a runtime loader. S1 enables supported Q heads and L1 enables the PPO loader without editing this frozen contract boundary.
9. Expose AppConfig.provided_fields as a frozen set of explicitly supplied dotted YAML paths, including shared game.* and rewards.* fields, captured before schema defaults are materialized. The resolved API distinguishes supplied values from legacy AppConfig defaults; preserve CLI/environment provenance separately at their resolver boundary. Consumers must not infer presence by comparing a value with a default.

## Acceptance evidence

- Every semantic field mutation changes the digest; reordering mapping keys does not. Array/channel order remains meaningful. Nonfinite/ambiguous contract fields are rejected.
- Legacy 58/61 and v2 checkpoint validation still works; v3 missing or mismatched metadata fails. Two same-seed CPU initializations and short RNG traces agree.
- Configuration schema/default reconciliation passes. No model topology, reward arithmetic or gameplay change occurs.
- A mixed batch of illegal-advised, advisory-empty, partially advised and dead rows resolves correctly without admitting an unavailable boost.
- A non-default YAML pqn block survives schema-to-AppConfig conversion exactly, with omitted fields remaining None, and a downstream consumer obtains it without reopening YAML.
- Q-head and actor/critic descriptor fixtures validate independently of observation shape; wrong output count, mismatched algorithm/head and unknown descriptors fail. Downstream S1/L1 can dispatch using the published API without modifying contract files.
- No config, a YAML file containing only pqn.lr, explicit game.mechanics_version/arena_type/num_snakes/max_frames and rewards.version, and explicit values equal to defaults all yield correct provided_fields. Omitted shared v1 defaults are distinguishable from an explicit v1 request.

## Compatibility and rollback

Revert additive APIs only before consumers land. After consumers land, roll back the dependent closure; never relabel a v3 artifact as v2.

## Handoff

Write command/result logs, source/config/checkpoint hashes, changed files, commit SHA, unresolved risks and interface changes to `<EVIDENCE_ROOT>/packages/c0/`. The root resolves EVIDENCE_ROOT to an absolute durable path outside disposable worktrees before dispatch. Obtain a root-issued test/compute slot before running commands. Return absolute artifact paths and hashes; root verifies the durable manifest before accepting the dependency or cleaning a worktree. A passing narrow test does not waive an upstream gate or promote a model.
