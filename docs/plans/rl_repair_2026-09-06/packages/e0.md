## Implementation / execution steps

1. Open and copy each candidate/baseline/opponent once into a content-addressed evaluation directory while hashing. Detect in-place mutation or fail; an atomic path replacement must not switch bytes halfway through the run.
2. Load snapshots for all seeds/mixes, deduplicate aliases by content hash, and retain original paths plus hashes, effective config, source identity and evaluator version.
3. Preserve scoring and existing diagnostic comparison behavior. Do not change promotion thresholds or copy authority until E2.
4. Do not expand this task into a general deserialization/security migration; existing trusted local loading remains a separate boundary.

## Acceptance evidence

- Replace a rolling source between seeded evaluations: all rows refer to the initial snapshot or the command fails before a verdict.
- Hash, config and source receipts round-trip; missing/corrupted snapshots fail. Aliased paths do not cause different content identities.
- Fixed-checkpoint scores and the paired/grouped-CI behavior remain unchanged on fixtures.
