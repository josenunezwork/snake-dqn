## Implementation / execution steps

1. Only actual death is a death terminal. Use the resolved advisory-then-legal set for v3 action selection and bootstrap; advisory-empty must not map to death_value. Preserve truncation bootstrap, exact gamma and valid-successor lambda carry rules.
2. Freeze hero/opponent assignments until their episode ends. Reference each opponent by immutable snapshot ID/content hash, never a mutable FIFO list index. Pin assigned snapshot objects until all assigned episodes finish; evict only unpinned snapshots and defer admission when every capacity slot is pinned. Add a shared rollout-policy interface for fixed common opponents or a versioned snapshot pool, with mode and realized exposure recorded.
3. Pass the active-env mask; discard finished rows without advancing their world/RNG. Reset the whole batch only at the existing boundary. Do not implement asynchronous reset here.
4. Retain the truthful continuation modes from P1. New episode and opponent state is explicitly fresh on continuation; record seeds, policy IDs and reset counters. The new recipe disables flip and retains legacy sampler, Adam, Huber and current network.
5. Report reward terms when available, valid hero kills/deaths/completed episodes, snapshot exposure, raw action frequencies, useful-row utilization, draws and optimizer work. Replace mislabeled rollout totals; keep legacy metrics clearly named.

## Acceptance evidence

- All-false-advice escape still bootstraps; actual death uses reward only; no lambda carry crosses invalid/dead/reset rows or a cap.
- Two rollouts inside one episode preserve policy identities/hero eligibility. Admit a new snapshot and attempt eviction between these rollouts: assigned snapshot hashes and deterministic actions remain identical. A fully pinned pool defers admission within its memory bound. Finished env snapshots/RNG do not change.
- Term/accounting totals reconcile with event fixtures; full/partial rollout and sampler tests remain green. N0 incidents preserve good state.
- Checkpoint/CLI receipts identify optimizer/odometer continuation and fresh episode/pool state. They do not advertise exact resume or silently imply that replay exposure continued unchanged.
