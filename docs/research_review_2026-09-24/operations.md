Represent initial state and later events separately; the space-ranking source's `second_*` fields cannot stand in for initial food. Declare which sources can support root-ID exclusion, raw initial-geometry exclusion, or neither. Missing information must produce an explicit inability to establish the required exclusion, not a permissive null match or an invented geometry.

Exercise each adapter and the actual analyzer-to-auditor interface on small fixtures before a future scientific freeze. Include missing fields, zero-replacement chunks, and the failing heartbeat call signature. Fixtures should encode the protocol's real gate and a deliberate violating example, so a checker cannot quietly add a stricter criterion. Share serialization and field definitions; retain independent verification of gate meaning. A shared implementation bug must not become agreement between two supposedly independent checks.

For future fresh-bank studies, qualify generator namespaces and descriptor novelty before costly training, under a prospectively approved blindness boundary. One option is a separate validator that seals descriptors and returns only the admission outcome; scientific evaluations still wait for fixed endpoints. Freeze what novelty means and which historical inventory it covers. Root IDs alone did not protect the horizon study from identical geometry. Do not apply this ordering change to its rejected bank or resample that bank.

## Priority 2: persist completion and define recovery

Use one stage-receipt format containing study and stage identity, input/code hashes, allowed operation classes, exit status, output hashes, and resource accounting. Persist append-only completion records at meaningful boundaries, with atomic finalization. The space-ranking extraction prefix disappeared in memory; the scaling audit prefix had to be inferred from source and failure location. Those are avoidable future ambiguities.

Distinguish an operation being announced, started, completed, and durably recorded. The counterfactual auditor incremented `raw_files_attempted` before its logging exception. A counter's name should not imply physical I/O it never measured. Likewise, the horizon supervisor's two exit-monitoring races were resolved from confirmed code-zero completion without repeating jobs; monitoring uncertainty should not automatically become a retry.

A **future** recovery policy can distinguish checker/serialization defects, scientific threshold failures, and ambiguous numerical execution. Specify allowed recovery stages, finite budgets, unchanged scientific criteria, required review, and durable-prefix requirements before admission. Preserve every failed attempt. Scientific failures must not trigger resampling, gate changes, or extra endpoints. Ambiguous execution stays stopped unless the approved policy resolves it. Existing zero-recovery protocols remain closed; this recommendation does not authorize a counterfactual audit retry or space-ranking extraction repeat.

## Scientific iteration cadence

Before another diagnostic, name the competing explanations and observation that would change the next experiment. Permit one bounded diagnostic block only if it changes an intervention or admission decision. If it redescribes the same failures, stop and synthesize. Further diagnostics need a new decision they can resolve.

Then prioritize one task-distribution and retention milestone that combines demonstrated skills over another small width/breadth comparison. Run a fixed, affordable learning comparison with predeclared endpoints and a fresh confirmation boundary. Report scientific outcome, engineering validity, and consumed compute separately. Use small/narrow Apex as a cost reference where appropriate, without calling it a promoted winner. Preserve the distinction between adaptive screens and independent confirmation.

Timebox harness work to the demonstrated contract, receipt, and state problems. Do not build a general workflow platform, automate hypothesis selection, lower failure thresholds, or let an agent convert a suggestive diagnosis into an automatic training continuation. Retain serialized numerical work and finite resource guards. After the next two authorized learning cycles, assess whether fewer stages became unusable and whether the experiments changed a scientific decision; avoid using report count, completed seals, or administrative throughput as success metrics.
