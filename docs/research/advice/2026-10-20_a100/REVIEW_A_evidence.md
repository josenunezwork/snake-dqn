## 3. Answer to the open question (from what survived)

1. **A100 does not shorten the time to a better served agent on any current stage.** The teacher is host-bound on the
   production layout (B8 forward 7.5–7.8% of worker wall, #6; ≤ ~13% in the diagnostic, #7 → Amdahl ceiling ≤ 1.15×
   even with free inference), and every A100 host record is 12 vCPU like L4 (#1). An A100 lane would do L4 work at
   ~3.2× the units unless a fresh assignment happens to have faster cores — unmeasured, and P5's own prior is 10–20%.
2. The fit is the only GPU-shaped stage, and it is unmeasured in production (#17); optimizer arithmetic is minutes
   (#16); the binding design already says "time one cached L4 fit first" (#15). Nothing is lost by following it.
3. The Mac-only chain is untouchable by any Colab hardware: remaining Phase 0 (59 frozen/mixed worlds, #20), Path B
   timing + pre-check + retention ≈ 27–28 h after Mac admission (#12), strict gate, serving qualification.
4. **What actually gets a better agent sooner:** (a) build and qualify the student-label → cache → fit → probe
   pipeline *now*, during the Phase 0/Path B wait — it is verifiably unbuilt (#10) and no accelerator bypasses it;
   (b) get a prospective judge ruling on the §5-vs-DESIGN:103 ordering conflict (#11) — the only thing that could put
   Colab label rounds in parallel with the Mac's Path B window (worth 1–2 calendar days if Path B runs long);
   (c) freeze the Claim B strict design and N now (P4c2 §6; P7 requires freezing before *its* data, not after
   Phase 0); (d) resolve the loss's correction-vs-retention conflict (#9) in the registered L3 2×2 before buying labels.
5. **One measurement worth buying: the first real cached L4 fit on production-shaped inputs with phase timing**
   (cache build / loader / fwd-bwd-Adam / held-out / probe / export), cap **8 u** (≤ 4 h at 2 u/h). It is on the
   critical path anyway, it is what DESIGN_V2:70-72 already requires, and it decides whether an A100-40 fit comparison

   and the records say it is the same host.
