# T34 O2: harvest added to rescue search

This package prepares a separately registered, one-look development comparison
of bare B8 s3, rescue-only D, and D+O. The question is whether harvesting adds
value beyond defense. O1's published GO is a mechanism result; O2 measures
complete terminal-hero H5000 trajectories on fresh paired worlds.

Authority: the owner's 2026-10-21 implementation request and
[`JUDGMENT.md`](../../docs/research/advice/2026-10-21_offense_vs_defense/JUDGMENT.md).
The contract, P7 statistics, exact action rule, banks, source identities, caps,
and analysis rule are frozen by `PREREGISTRATION_O2.md` and the create-only
`REGISTRATION_O2.json`. No O2 study outcome exists at preparation time.

The implementation imports O1's provenance and branch evaluation and existing
T34/T3 search code without modifying those packages. All inference is CPU fp32,
including on L4 hosts. L4 is the registered Colab machine type, not a CUDA
inference request. Mac work is limited to excluded tiny preflight fixtures with
nice 10 and at most two numerical threads.

Prepared supervisor manifests, input sidecars, the preflight receipt, and
`DISPATCH.txt` live outside Git in
`/Users/josenunez/Projects/ml/snake-dqn-artifacts/t34-o2-20261021/`.
They are locally validated through `research.colab_cli`; no Colab allocation,
execution, authentication, or dispatch is authorized by this preparation.
The dispatch document identifies the exact published commit and commands for a
future operator. Every world keeps its three arms on one worker/CPU model.

An O2 GO is development evidence only. A candidate still needs the Mac paced
test, a fresh Mac strict gate, serving qualification, and the owner's release
approval. Product Watch6 bars are evaluated in that later paced stage; O2
terminal worlds do not substitute for continuous-respawn paired sessions.
