# Job A A-2: resident collector and learner throughput repair

**Status:** current development protocol. This document supersedes the A-1
runtime description in `README.md`. It is governed by
[`ADOPTED.md`](../../docs/research/governance_a100_sandbox_20261026/ADOPTED.md)
and is simulator-D engineering evidence only. It neither selects a policy nor

evaluation. `research/colab_cli` is outside this change.

## Purpose and scope

The A-1 A100 attempt passed its resident correctness and capacity checks, but
collection was the limiting cost: the recorded A100 summary reports about 493
useful hero rows/s at E128 and 1,862 at E1024, while the learner processed about
30,000 rows/s. Argon's review attributes the cycle-to-cycle slowdown primarily
to per-tick, tiny-batch truncation bootstraps and subset resets. A-2 measures
the same finite resident assay after removing those runtime costs. It is not a
quality, policy, gameplay, or historical P1 comparison.

The only frozen model input remains B8 s3, SHA-256
`3e64978337b67b7acaf4daa93bdefa827d8296bcb0f63413886a1aaad12eb4f8`.
There is one sampled hero and five `greedy_food` anchors. PPO remains fp32,
with gamma 0.99, lambda 0.95, clip 0.2, Adam learning rate 0.0003, value
coefficient 0.5, entropy coefficient 0.01, and grad-norm clip 0.5. The A-2
learner uses one epoch and a 2,048-row minibatch.

## Fixed A-2 matrix

Each of the 12 cells has H128, one excluded warmup, and three measured cycles.
Cached reports learner-processed rows only; collection and integrated report one
useful hero row per world/tick. Six snake seats never count as six useful rows.

| World count | Episode limits | Phases | Measured cells |
| --- | --- | --- | --- |
| E128 | 64, 512 | cached, collection, integrated | 6 |
| E1024 | 64, 512 | cached, collection, integrated | 6 |

The `episode_limit=64` cells preserve the truncation-churn stress case. The
`episode_limit=512` cells measure the realistic-length alternative. Each
collection or integrated cell must include a measured truncation; a cell without
one is invalid rather than silently treated as equivalent.

The namespace remains `a100-dev/sandbox-a`. A-2 uses fresh, disjoint allocation
offsets 20,000,000 through 31,000,000, one million apart, in the deterministic
control order: episode limit, world count, then phase. The same-device proof
uses offset 90,000,000. The registry checks every possible reset root, rejects
zero/effective-63-bit aliases and protected intersections, and binds the empty
verified ledger. No A-1 result or receipt is an A-2 resume input.

## Runtime changes under test

Argon's top-ranked runtime repairs are the A-2 implementation contract:

1. Defer truncation bootstrap observations and critic evaluation until after the
   horizon, then evaluate the saved live truncation states in one batch. The
   deferred observations must be byte-equal to the previous per-tick result;
   critic values use a 2e-5 float32 batch-reduction tolerance (CPU), with a
   nonzero value head in the independent pre-reset seam oracle.
2. Reset selected worlds in place. Do not form a subset simulator through the
   former full field `index_select`/`index_copy_` path, and do not retain a
   full-E empty simulator clone. Live rows must remain unchanged.
3. Use one advisory mask per tick for both hero observation and anchor actions,
   preallocate row, zero-Q, action and rollout storage, and replace the old per-tick host-visible
   `.nonzero()` decisions with mask-based device operations.
4. Preallocate rollout buffers and fill them by index. Do not clone every
   per-tick value or stack complete per-tick lists at the horizon boundary.
5. Timing cells set deterministic algorithms off and TF32 on for CUDA matmul
   and cuDNN. The exact-resume proof alone sets deterministic algorithms on and
   TF32 off. Both complete numerical-setting records belong in `summary.json`.

`torch.compile` was Argon's sixth-ranked follow-up. The runtime prepares an
explicit `compile_mode` hook (`none` or `default`) for CUDA actor and GAE work,
with no silent fallback. The A-2 manifest fixes `compile_mode=none`, so this
eager baseline makes no compiled GPU timing or qualification claim. A future
compile experiment requires a fresh packet and output identity; it cannot be
added to this sweep after observing A-2.

Ordinary eager Torch arithmetic still creates tensor intermediates; this is not
a zero-allocation or host-free simulator claim. These changes may alter
floating-point execution in the timing mode. They do
not license an old whole-training trajectory to be called bit-equal. The only
bit-equality claim for complete training state is the same-platform full-state resume proof run in the
deterministic proof mode. It includes collection, masks, resets, GAE, actor,
optimizer, RNG, and the next update; it is not a cross-platform claim.

## Correctness and result requirements

Before dispatch, the implementation must retain and run checks for legal-mask
log-probability and entropy gradients, GAE against an independent reference,
terminal-versus-truncation bootstrap handling, and deterministic same-platform
resume. It also adds the deferred-bootstrap equivalence check against the former
per-tick computation. Tests run at `nice -n 15` with one math thread and without
xdist.

Every measured cell must export its three cycle timings and useful/processed
rows/s. The result records mean, min, max, coefficient of variation, and the
last/first cycle-rate ratio, so a high average cannot hide recurrent slowdown.
It also records collection/GAE/reset time, learner time, setup/export time,
reset/terminal/truncation counts, peak device memory, and the timing numerical
settings. The actual local commands, test counts, timings, preflight, and
dry-run output belong in `VERIFICATION_A2.*`; this protocol supplies no GPU
timing result itself.
