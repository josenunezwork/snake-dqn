1. Consume C0's complete validated AppConfig, including frozen PQNOverrides, once; never reopen YAML. Map every supported dynamics field into BatchSimConfig. Reject unsupported/conflicting fields explicitly; validate cell alignment rather than silently rounding geometry.
2. Use C0 provided_fields plus explicit CLI overrides to preserve the current legacy PQN no-config and partial-config defaults. A YAML file containing only pqn.lr must not import omitted AppConfig mechanics/reward-v1 defaults. When a named v3 recipe is explicitly selected, resolve its complete world and overlay supplied supported fields in the frozen precedence order. Record the effective value and source for every field; an explicitly requested unsupported reward-v1 still fails.
3. Test the audited 777 x 666 fixture as fail-fast for unsupported divisibility where applicable, plus a grid-aligned non-default fixture that propagates every field. This avoids mandating an invalid world just to mirror the audit input.
4. Honor device precedence and seed all RNGs before model/environment construction. Reject PQN reward_version !=2 until a real v1 dispatch exists; record kill/death coefficients and actual arithmetic.
5. Add recipe/world/observation/mask/runtime/source metadata. Keep successful N0 recovery. Restore optimizer hyperparameters truthfully; conflict between requested and resumed values fails or uses explicitly named weights-only warm start.
6. Initial implementation exposes weights-only warm start and explicitly labeled optimizer/odometer continuation with fresh environment/pool state. Capture/restore only the RNG streams actually supported and name any reset streams. Reject an exact-resume request: full simulator/pool/IPC continuation is deferred, not an optional branch depending on future P2 code. Legacy checkpoints remain inference-compatible. A checkpoint lacking any required training recipe/episode provenance is weights-only for new training; optimizer/odometer continuation is rejected. No unverified continuation escape hatch is included in this repair.

- Resolved simulator, logs and checkpoint agree on every supported world field, requested/effective device and active optimizer learning rate.
- Explicit --seed repeats initial parameter hashes. Requested LR 0.0002 versus saved 0.001, max_frames 100 to 40, and epsilon horizon 100 to 10 fail conflicting optimizer/odometer continuation unless a named weights-only warm start is selected. - No-config and PQN-only YAML retain legacy PQN mechanics/reward defaults; explicitly supplied shared fields propagate or fail as documented. Selecting the v3 recipe produces its complete resolved world without accidentally importing omitted legacy AppConfig defaults. Verify value and provenance for each case.
