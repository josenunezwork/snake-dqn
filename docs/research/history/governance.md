Pinning SciPy cannot repair this last-bit SHA difference. A 76-test numerical preflight runs before the full suite.

Full-suite and per-commit hosted results were checked via `gh run list` / `gh run view` (not recorded in the note).

## What Was Learned

- **Cross-architecture numerics break bitwise parity:** Mac ARM64 vs x86 pods diverge on exact float32 Q ties (~1 in 50 H10000 episodes), and Linux vs Darwin `erf` differs in the last bit for SHA-pinned `NormalDist` tables; strict gates stay on the Mac and the CI Python job runs on macOS ARM64 ([`governance_amendment_strict_on_runpod_2026-10-05_status_2026-10-08.md`](../governance_amendment_strict_on_runpod_2026-10-05_status_2026-10-08.md), [`t14_ci_validation_2026-10-17.md`](../t14_ci_validation_2026-10-17.md)).
- **Match the unit of inference to the source of randomness:** five training seeds are the unit only for recipe claims; fixed controllers (Path B over frozen B8) have none, so P7 uses the paired world ([`2026-10-19_rules_audit_fable_judgment.md`](../advice/2026-10-19_rules_audit_fable_judgment.md)).
- **Separate exploration speed from confirmation rigor:** the 2026-10-30 Fast-Process Rule removed pre-registration ceremony from exploration while keeping pre-data bars, fresh/held-out worlds and paired statistics for confirmation runs ([`AGENTS.md`](../../../AGENTS.md)).
