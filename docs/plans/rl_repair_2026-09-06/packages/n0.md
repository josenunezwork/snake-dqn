## Implementation / execution steps

1. Check targets, loss and gradients before optimizer.step; stop remaining minibatches on failure. Validate parameters and optimizer state after the step. Keep a last-known-good recovery strategy whose memory cost is measured.
2. For every tripwire, persist exception telemetry and incident cause before exit. For pre/post-step nonfinite failures, restore the last-known-good training state and keep latest unchanged. For finite max-Q and finite action-collapse alarms, retain existing detection thresholds and halt timing, preserve the previous accepted latest, and save the finite flagged state only as an explicitly labeled incident checkpoint. If no good latest exists, leave it absent.
3. Distinguish tripwire classes in the incident schema and checkpoint history. Preserve opt-in sampler controls and successful-update arithmetic. Moving a finite flagged model out of latest is an intentional checkpoint-safety change; do not silently change alarm thresholds or suppress finite diagnostic artifacts.

## Acceptance evidence

- Inject nonfinite target, loss, gradient and post-optimizer state separately. Existing latest bytes remain unchanged; all incident fields are persisted; no later minibatch runs.
- Finite control updates and checkpoint outputs match baseline on deterministic fixtures. Atomic-write interruption tests remain green.
- Reproduce the old failure with the retained audit fixture and demonstrate its corrected postcondition, using disposable paths only.
- Inject finite max-Q and finite action-collapse alarms separately: the existing trigger/halt condition remains, latest bytes remain unchanged, and the labeled incident checkpoint, classification and telemetry are loadable and complete. Post-step nonfinite recovery restores optimizer state as well as weights.
