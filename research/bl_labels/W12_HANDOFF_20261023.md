## Calibration

Wait for the running M-E's terminal receipt and shared lease release. Run the
new scripts from their published implementation commit, using tools/ops to
create a clean pinned worktree and provide caffeinate, AC/lid checks and logging.
The new runner verifies frozen executable bytes against the pack's
`61900af28932e47e22e332840fc4406559adb062` source pin. Its own file SHA is recorded
separately; receipt `code_sha` remains that frozen F0_COMMIT.

The calibration bank is the frozen 64-root F1 bank
`a8c1dc4bbe1fd579d59b69d6ca6ca9dbd2814b088f74277f008f504f6d1bbb0d`.
Preparation replays the recorded source tapes once. Each cell warms its workers
on one complete bank, then measures three complete banks (192 ordered roots).
Paired cells run W6/W12, then W12/W6, alternating thereafter, for at least three
pairs and at least 1,800 seconds of complete measured windows. Preparation,
worker startup and warmup never contribute to that minimum. No time-padding
sleep or label/rescue outcome summary is used. Full digest, neutral digest,
label hash and bare-audit integrity must agree across every repeat and width.

The ratio is **worker-wall per unit**:

`(12 * sum(W12 wall) / W12 units) / (6 * sum(W6 wall) / W6 units)`.

Each width's first measured 192-root cell freezes its slowdown baseline;
a later same-width cell above 1.30 times that baseline trips. AC/lid, parsed
pmset therm, disk and owned-worker RSS are sampled about every five seconds,
with operational heartbeats about every 55 seconds. Unknown observations fail
closed. The shared Mac lease and canonical timing arm protect timing/strict
work. Created worker pools terminate and join before lease release; no existing
process/session is signalled. The whole-run cap is two hours, including startup,
preparation and warmup. This is a calibration cap, not a D256 cap amendment.

The runner writes a create-only `receipt.json`, SHA sidecar and completion marker
to `bl-labels-f0/w12-calibration-01`. A PASS has exactly the admission fields
required by `_verify_w12_calibration`: schema
`bl-labels-f0-w12-calibration/v1`, measured duration >=1,800 seconds,
0 < normalized ratio <=1.30, thermal_not_ok=0, slowdown_trips=0,
darwin-arm64 and frozen F0_COMMIT. Additional fields bind the owner approval,
checkpoint hashes, runner, bank, measured cells, host-sample log and lease.
Failed attempts remain immutable. A new calibration attempt needs a fresh
`--output` and the D256 script's matching `--calibration-receipt` override.

## Production admission and fallback

After calibration exits and the complete M-E/F0 and actual F4 approval exist,
run `RUN_D256_W12.sh` with that actual F4 judgment path. The script verifies
calibration provenance, telemetry and checkpoints before calling the frozen
admission gates. A PASS selects W12 and passes `--owner-w12-ok` and
`--w12-calibration-receipt` to both the driver check and execution. A sealed
measured ratio/slowdown FAIL selects W6. Missing/tampered receipts, HOLD,
preemption, unknown host state and failed F1/F0/F4 gates stop; they never
trigger a production fallback. Current healthy host conditions are still
required at either width. This script does not run calibration automatically.

All writes go to the fixed sibling `bl-labels-f0/mac-d256-w12-01`.
Only six prerequisite triplets are copied byte-for-byte; original F1/F0 receipt
paths and the global F0 look claim remain canonical. No look is repeated, and
the 864-parent namespace/allocation and 57,600-second cap are unchanged.
Any original D256 admission, output, accounting state or nonempty ledger stops
relocation. Use this launcher as the sole D256 start; do not also run the old
pack's RUN_D256.sh. No new approval is manufactured.

A failed lease acquisition or pre-execution check may leave a prepared sibling.
The same script can continue (with a fresh tools/ops job name/log) only if every copied triplet still matches,
every entry is one of those triplets or the sealed admitted control, and there
is no output/state/attempt evidence, including empty directories. Existing
admission dependencies and the same F4 approval path are rechecked. Any actual
attempt evidence means HOLD: retain the sibling and use the existing frozen
driver's reviewed ledger/accounting resume process; never delete/reset it.

## Commands

Set `RUNNER_SHA` to the published commit in the final operator handoff.
These are sequential submissions: inspect the calibration terminal receipt and
lease release before submitting D256. `--check` on the calibration script is a
read-only input/source preflight and can be run while M-E is active.

```bash
SOURCE=/Users/josenunez/Projects/ml/snake-dqn-f0
RUNNER_SHA=<published-implementation-SHA>
bash "$SOURCE/research/bl_labels/RUN_W12_CALIBRATION.sh" --check
"$SOURCE/tools/ops/mac_run.sh" --repo "$SOURCE" bl-f0-w12-cal-01 "$RUNNER_SHA" -- \
  /bin/bash research/bl_labels/RUN_W12_CALIBRATION.sh

# After calibration ends, and F1/F0/F4 are admitted: W12 PASS or measured-FAIL W6.
"$SOURCE/tools/ops/mac_run.sh" --repo "$SOURCE" bl-f0-d256-w12-01 "$RUNNER_SHA" -- \
  /bin/bash research/bl_labels/RUN_D256_W12.sh \
  /Users/josenunez/Projects/ml/snake-dqn-artifacts/bl-labels-f0/mac-pack-02/inputs/judgment.json
```

The real 30-minute calibration and D256 remain operator steps. Lightweight
single-process tests use fake clocks/pools for sustained-duration scheduling and
recovery. Their passing result is implementation evidence, not calibration PASS.
