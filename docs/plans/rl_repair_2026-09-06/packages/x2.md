## Implementation / execution steps

1. Consume G1's one-100k-shakedown-per-algorithm cost receipts, then run five fresh paired training seeds with 500k hero transitions per arm. Run all 10 arms serially with unchanged settings and fixed common opponents. Recalibration after any recipe/source change requires a new protocol.
2. Use a new development world set; evaluate each final/initial checkpoint and anchors. Predeclare primary per-trained-seed paired mass delta, fixed absolute practical-effect margin from independent calibration, and seed/mix aggregation.
3. Record parameter counts, environment frames, useful hero rows, optimizer updates, wall time and memory. Equal data is not equal compute; report both.
4. Use per-arm cost/resource caps calibrated before score inspection. Wide intervals remain inconclusive. Do not extend or select hyperparameters on these evaluation worlds.
5. Verify the frozen observation preprocessing and conv/fusion trunk fingerprint and paired initial trunk weights match across algorithms; only predeclared output heads and algorithm-required update rules may differ. A trunk mismatch stops this algorithm-only protocol rather than being excused by recording parameter counts.

## Acceptance evidence

- Complete raw outcome cardinality and immutable hashes; five independent paired training units, not 60 world rows counted as 60 trained models.
- Superiority, practical equivalence and inconclusive outcomes are distinct. A selected method still needs a separately chosen checkpoint and final live gate.
- The paired architecture manifest has identical preprocessing/trunk fingerprints and initial trunk weights. Unplanned width, depth, normalization or initialization differences invalidate an algorithm-effect claim and require a distinct architecture protocol.
